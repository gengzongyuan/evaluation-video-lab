# 首轮视频事实核验包

> 目的：在拍摄前确认口播中的方法论主张有可靠依据，并把示意数字与真实结果分开。本文不替代本项目的模型实测；在拿到原始实验记录前，视频只能按“方法教学”发布。

## 使用规则

- **示意数字**（如 81/80、8/6/7、总分 90）只用于讲解计算方法，画面和字幕必须持续标注“示意”。不得写成模型、版本或产品结论。
- **真实结果**须同时保存：输入样本、模型/版本、提示词、参数、运行日期、评分规则、原始输出和失败样本。缺一项，结论降级为 L1（单次演示）或“待核验”。
- 外部来源只支持“为什么要这样测”的方法论，不支持“某模型最好”。模型排名、价格、版本和效果差异必须回到本项目自己的记录。

## 视频 01：排行榜与误差

| 脚本主张 | 核验结论 | 证据要求/拍摄处理 |
|---|---|---|
| 不同任务（知识、代码、长文本、工具调用）可能产生不同排序 | 方法论成立；不推出任何具体模型排名 | 画面用抽象卡片；若出现真实榜单，保存其任务定义、样本和评分说明，并标明来源与检索日期 |
| 同叫“准确率”的数字，因数据集、评分规则、运行次数不同而不可直接横比 | 方法论成立 | 口播改为“需要先核对定义和条件”；不要说成所有榜单都不可信 |
| 单次 81 分 vs 80 分，若波动约 2 分，不能据此断言真实领先 | 统计解释成立，但 81/80/±2 为示意 | 屏幕标注“示意”；真实拍摄时至少展示重复运行结果和波动计算，必要时给出置信区间或 bootstrap 区间 |
| 可靠评测应交代任务范围、样本量、评分规则、重复次数、原始结果 | 作为透明度清单成立 | 使用五格证据卡；不能暗示公开了这些字段就自动保证评测正确 |

**建议核验来源（方法论）**

1. NIST，*Artificial Intelligence Risk Management Framework (AI RMF 1.0)*：强调记录测试集、指标、限制和适用范围。https://www.nist.gov/itl/ai-risk-management-framework
2. ISO/IEC 25059:2023，*Software engineering — Systems and software Quality Requirements and Evaluation (SQuaRE) — Quality model for AI systems*：用于说明 AI 质量评价需要定义质量属性和评价条件。标准正文可能需购买，引用时只写标准号和标题。
3. Stanford CRFM，*HELM: Holistic Evaluation of Language Models*：展示多场景、统一条件和可复核结果的重要性。https://crfm.stanford.edu/helm/latest/

## 视频 02：一次评测为什么不够

| 脚本主张 | 核验结论 | 证据要求/拍摄处理 |
|---|---|---|
| 单条样例不能代表稳定能力 | 方法论成立；不能量化代表性阈值 | 口播用“不能单独证明”，不要声称“一定会反转” |
| 生成式模型同一问题可能出现不同答案 | 需绑定随机采样条件；并非所有设置都会变化 | 拍摄时显示 temperature/top-p/seed 等参数；若使用确定性设置，明确“本次设置下可复现” |
| 最小闭环应包含任务、多个样本、统一评分、失败记录 | 作为项目工作流建议成立，不是行业硬性标准 | 说“本系列建议的最小闭环”；不要说“所有评测至少必须 X 条” |
| 应同时查看总体分、波动和关键失败 | 决策建议��立 | 对真实实验保留分组分数、重复运行汇总和失败样本；平均分不能替代业务红线检查 |

**建议核验来源（方法论）**

1. OpenAI，*Evals*：说明评测样本、记录和可重复运行的实践。https://github.com/openai/evals
2. Stanford CRFM，*HELM*：多指标、多场景评估；支持“不要只看一个总分”的方法论。https://crfm.stanford.edu/helm/latest/
3. NIST，*AI RMF Playbook — Measure*：建议记录指标、测试条件、误差和限制。https://www.nist.gov/itl/ai-risk-management-framework/ai-rmf-playbook

## 拍摄前逐条核验单

- [ ] 每个数字都标成“示意”或有对应实验记录 ID。
- [ ] 每个模型名、版本号和日期都能回指原始记录。
- [ ] 每个“更好/领先/提升”都写明任务、样本、评分规则和比较基线；缺条件则改为“本次结果”。
- [ ] 随机性演示记录采样参数；固定 seed 或 temperature=0 时不口播“必然随机”。
- [ ] 真实结果至少保留原始输入、原始输出和失败样本；截图不能替代原始文件。
- [ ] 引用外部数字时记录 URL、标题、检索日期（2026-11-21）和上下文；无法打开或无法复核则删除数字、降为待查线索。
- [ ] 发布元数据中的 `claim_level` 与证据一致：无真实多样本结果时最多 L1；跨模型公开方法与原始数据齐全才考虑 L3。

## 可直接替换的安全口播

- “下面的 81 分和 80 分是**示意数字**，只用来说明误差，不代表任何模型。”
- “这次演示说明的是**评测方法**；它不能推出哪个模型在所有任务上更好。”
- “同一问题是否变化，取决于采样参数和服务实现；我们先把条件记录下来，再比较结果。”
- “这是本系列建议的最小闭环，不是一个对所有业务都适用的固定样本量标准。”
