# LF-08《用户反馈如何回流 Score》Xiaoxiao 分镜板

用途：按 `zh-CN-XiaoxiaoNeural`、`rate=-5%` 为 20 段口播制作画面。口播多长，成片就多长；禁止拉伸到固定 180 秒。状态保持 `prototype / L1`。

## 制作规则

- 20 镜使用 20 种不同构图，相邻构图不得重复。
- 每镜画面内只烧一条短字幕，完整口播保留在「口播」列。
- 点赞、点踩、评论、Score 和样本分布都是示意，不是真实用户数据。
- 反馈关联字段与 SDK/API 参数以录制当天官方文档和部署版本为准。
- 无内网地址、密钥、Authorization 值、PII、完整 Prompt 或真实用户评论。

## 20 镜分镜

| 镜 | 构图 | 时长提示 | 口播 | 画面 | 烧录字幕 |
|---:|---|---|---|---|---|
| 01 | `hook` | 6–10s | 一个用户点了踩，能不能说明大家都不满意？不能。先把这条反馈和它对应的回答对上。 | 巨大点踩图标旁只有一条反馈卡，整体满意度仪表保持空白 | 一条点踩，不能代表所有用户 |
| 02 | `single-event` | 6–10s | 点赞或点踩首先是一条具体反馈事件，它只说明某个人在某个上下文里的反应。 | 单条事件卡：反馈类型 / 时间 / 脱敏上下文 | 反馈先是一条具体事件 |
| 03 | `trace-link` | 6–10s | 要让反馈有用，先关联到原始 Trace 或 Observation，找回当时的输入、输出和中间步骤。 | 反馈卡连接 Trace 树与原始输入输出，ID 用占位符 | 把反馈和原始 Trace 对上 |
| 04 | `context-card` | 6–10s | 只留一个“差”，很难知道该改哪里。还要保留当时版本、运行时间和必要的脱敏上下文。 | 上下文卡包含版本、时间、Trace ID，不包含用户原文 | 反馈要带上运行版本和上下文 |
| 05 | `type-grid` | 6–10s | 点赞、评分和文字评论是不同反馈类型。先定义类型，再决定怎么记录和分析。 | 三格类型卡：thumbs / rating / comment，互不混用 | 点赞、评分、评论不是同一种数据 |
| 06 | `scale` | 6–10s | 数值反馈要明确取值范围和含义。不同产品的“一分”和“五分”不能直接混在一起。 | 两组不同量表被分隔，标注范围与定义 | 先定义取值范围，再比较分数 |
| 07 | `comment-split` | 6–10s | 没有标签的评论不能直接当成分数。要么人工定义映射，要么作为文本单独分析。 | 评论卡进入两条分支：人工规则 / 文本分析，禁止自动数值化 | 没有标签的评论，不直接当分数 |
| 08 | `null-box` | 6–10s | 用户没有反馈，不代表满意，也不等于零分。缺失反馈要按空值处理。 | 未反馈样本进入 unknown 盒，不进入好评或差评 | 没有反馈 ≠ 满意或零分 |
| 09 | `source-lanes` | 6–10s | 记录反馈来源，区分真实用户、人工标注和自动生成，避免把来源不同的分数混算。 | 三条来源泳道：user / human / model，汇总前需分组 | 反馈来源不同，不能不加区分地混算 |
| 10 | `binding-map` | 6–10s | 按当前 SDK 或 API 把反馈绑定到正确的 Trace 或 Observation，并保存关联 ID。 | 绑定地图：feedback → Trace / Observation，字段按版本核对 | 反馈要绑定到正确的运行对象 |
| 11 | `readback-loop` | 6–10s | 写入之后，用同一个 ID 回读 Score 或事件，再核对原始输入输出和反馈值。 | 写入 → 关联 ID → 同一条回读闭环 | 同一个 ID 回读反馈和原始记录 |
| 12 | `response-ticket` | 6–10s | 只有 2xx 写入响应，还不能说回读成功。响应、关联和回读是三件不同的事。 | 2xx 回执停在回读门前，关联字段仍待核对 | 写入 2xx ≠ 反馈回读成功 |
| 13 | `pos-neg` | 6–10s | 抽查时不要只看好評，也要看差评和空值。正负例都可能藏着记录或理解错误。 | 正例、负例、空值三列抽样卡同时展开 | 好评、差评和空值都要抽查 |
| 14 | `silent-majority` | 6–10s | 愿意反馈的人往往只是少数。没看到差评，可能只是大多数用户没有开口。 | 少数发言气泡旁是大片沉默用户轮廓 | 没反馈的人，不一定都满意 |
| 15 | `denominator` | 6–10s | 汇总时要写清样本量、覆盖范围和采样方式。只看百分比，不知道分母，结论就不完整。 | 百分比旁放大分母和采样框，数值留空 | 反馈百分比必须带分母和采样范围 |
| 16 | `redaction` | 6–10s | 评论原文可能带个人信息。进入仓库、Dataset 或公开视频前，要先脱敏并控制权限。 | 原文卡经过脱敏遮罩，再进入受权限保护的样本库 | 评论原文先脱敏，再进入样本库 |
| 17 | `dataset-return` | 6–10s | 有价值的正负反馈可以经审核进入 Dataset，作为下一轮回归素材，但要保留来源和版本。 | 审核后的反馈样本回到 Dataset，保留 source 和 version | 反馈样本审核后再进入 Dataset |
| 18 | `regression-board` | 6–10s | 放进 Dataset 也不等于问题已修复。还要固定版本重跑，比较失败样本有没有变化。 | 回归看板：旧版本 / 新版本 / 同一失败样本，结果留待实测 | 进入 Dataset ≠ 问题已修复 |
| 19 | `stamp` | 6–10s | 本集画面是 prototype、L1 示意，不代表当前实例已收到反馈、写入 Score 或完成回读。 | PROTOTYPE / L1 印章，反馈、Score、回读全部标未证明 | prototype / L1：不是反馈已回流 |
| 20 | `cta` | 6–10s | 下一集讲生产治理：采样、脱敏和保留策略，怎样避免记录越多、风险越大？ | LF-09 预告卡：采样率、脱敏、保留期限三个控制开关 | 下一集：采样、脱敏和保留策略 |

## 固定构图顺序

`hook → single-event → trace-link → context-card → type-grid → scale → comment-split → null-box → source-lanes → binding-map → readback-loop → response-ticket → pos-neg → silent-majority → denominator → redaction → dataset-return → regression-board → stamp → cta`

## 字幕与旁白

- 声线 `zh-CN-XiaoxiaoNeural`，`rate=-5%`，禁止整段变速。
- 首次出现保留英文并给中文解释：Trace 运行记录、Score 评分、Dataset 数据集。
- 烧录字幕使用表中短句；SRT、VTT 使用同一时间轴，最后一条与片尾对齐。
- 不编造用户数量、满意度、正负反馈比例或回归结果。

## 演示与证据边界

1. 录制时保存反馈类型、范围、来源、时间、关联 ID 和当前 SDK/API 版本。
2. 回读同一 ID 的 Score 或事件，并抽查正例、负例和空值。
3. 评论进入样本库前脱敏、审核和权限控制；反馈进入 Dataset 不等于问题已修复。
4. 单条反馈、单次写入或一个百分比不能推出总体满意度。
5. 当前文件只定义概念课画面，不证明当前实例已收到、写入或回读反馈。
