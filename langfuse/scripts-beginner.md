# Langfuse 微课 01–03：入门脚本包

> 本文件把 Langfuse 官方概念转成 3 条约 3 分钟的可拍脚本。演示以 Langfuse 当前官方 SDK/API 文档为准；运行前应锁定 SDK 版本、Langfuse 部署版本和检索日期。示例代码中的密钥必须使用环境变量，不能写入视频或仓库。

## 第 01 集｜Langfuse 是什么：给 LLM 应用装一台“黑匣子”

**一句话结果**：观众能说清 Langfuse 解决的是“看不见 LLM 调用过程”的问题，并知道一条最小接入链路：应用调用 → 上报观测 → Langfuse 查看。

**时长与时间轴（约 180 ���）**

| 时间 | 口播 | 画面 |
|---|---|---|
| 0–12s | “你的 AI 应用回答错了，日志里却只有一句‘请求失败’。到底是哪一步错了？” | 黑屏日志切到 Langfuse Trace 结构；字幕：`看见调用过程，才能定位问题`。|
| 12–35s | “Langfuse 是面向 LLM 应用的可观测与评测平台。它把一次用户请求里的模型调用、工具调用、提示词、耗时和结果串起来。” | 画出 User request → Trace → Span/Generation → Output。|
| 35–70s | “它不是模型，也不是替你生成答案的聊天机器人。它记录并组织运行证据，帮助你回答：发生了什么、花了多久、花了多少钱、结果是否值得信任。” | 三张卡：过程、成本、质量；标注“能力范围”。|
| 70–115s | “最小链路有三步：在应用里初始化 SDK；为一次请求建立 Trace；把模型调用作为 Generation 上报。” | 屏幕录制官方 SDK quickstart；密钥区域打码。|
| 115–145s | “接入后，先看一条 Trace，而不是先做漂亮的仪表盘。确认输入、输出、时间和状态都能回看。” | Langfuse Trace 详情页；依次圈出 input/output/latency/status。|
| 145–170s | “第一集只证明‘事件能被看见’，还不能证明模型质量，也不��证明成本统计已经准确。” | 绿色“已验证：可观测链路”；黄色“待验证：质量/成本”。|
| 170–180s | “下一集我们拆 Trace：一次请求为什么要有一棵调用树？” | 片尾卡：`下一集：Trace 是什么？`。|

**可运行演示步骤**

1. 按官方安装页选择 Python 或 JS/TS SDK，固定版本并记录日期。
2. 在本地环境变量中配置 `LANGFUSE_PUBLIC_KEY`、`LANGFUSE_SECRET_KEY`、`LANGFUSE_HOST`（云端或自托管地址）。
3. 运行官方 quickstart 示例，发送一条脱敏输入。
4. 在 Langfuse UI 搜索刚刚产生的 Trace，核对 input、output、时间和状态。
5. 保存运行日志与 Trace URL/ID；视频只展示脱敏数据。

**官方来源**

- Langfuse Documentation：<https://langfuse.com/docs>
- SDK 入门入口：<https://langfuse.com/docs/sdk>
- GitHub 主仓库：<https://github.com/langfuse/langfuse>

**事实边界**：Langfuse 的具体菜单、SDK 方法名和字段可能随版本变化；视频不得把当前 UI 截图当作永久 API 契约。

## 第 02 集｜Trace 是什么：把一次请求还原成调用树

**一句话结果**：观众能用 Trace、Observation、子调用三个词解释一次 LLM 请求，并能在 UI 中定位一个失败节点。

**时长与时间轴（约 180 秒）**

| 时间 | 口播 | 画面 |
|---|---|---|
| 0–10s | “用户只发了一句话，后台可能跑了检索、重写、工具和模型四步。只看最终答案，你看不出哪一步拖慢或出错。” | 一句话变成四节点调用树。|
| 10–35s | “在 Langfuse 里，一次可追踪的应用请求可以看成一个 Trace。Trace 是容器和关联上下文，不是某一个模型答案。” | Trace 外框包住多个 Observation。|
| 35–75s | “树里的每个 Observation 代表一个可观察动作：模型生成、普通处理、检索或工具调用。父子关系让你从总耗时钻到具体节点。” | UI 展开父节点；动画显示 duration 累加。|
| 75–115s | “演示一个 RAG 请求：先建 Trace，再记录检索 Span，再记录回答 Generation。最后回到 Trace，看输入、输出、延迟和错误。” | 录屏或代码片段；逐步高亮三节点。|
| 115–145s | “排错时先问三个问题：失败节点是哪一个？它的输入是什么？它耗时和输出是否异常？” | 三问卡片；一个节点变红。|
| 145–170s | “Trace 能帮你定位一次运行发生了什么，但单条 Trace 不能代表整体稳定性。要看趋势，还得汇总多次运行。” | 单条证据 vs 趋势图对照。|
| 170–180s | “下一集区分 Span 和 Generation：为什么模型调用要单独记？” | 片尾卡。|

**可运行演示步骤**

1. 使用官方 SDK 的当前 Trace/Observation 示例创建一个请求上下文。
2. 在同一请求内记录一个检索或工具调用，再记录一次模型生成。
3. 让演示故意制造一个可控错误（例如缺少输入字段），观察错误节点和 Trace 状态。
4. 在 UI 按 Trace ID 打开详情，核对父子层级、时间和错误信息。
5. 清除真实用户内容、密钥和个人信息后录屏。

**官方来源**

- Tracing 概念：<https://langfuse.com/docs/observability/overview>
- Observations / Trace 数据模型：<https://langfuse.com/docs/observability/data-model>
- SDK 文档：<https://langfuse.com/docs/sdk>

**事实边界**：不同 SDK 版本可能把创建 Trace、Observation 的方法名调整为不同 API；视频口播使用概念名，代码画面标注 SDK 版本。

## 第 03 集｜Span 和 Generation：把“普通步骤”和“模型调用”分开

**一句话结果**：观众能判断一个步骤应该记录为 Span 还是 Generation，并知道分开记录对耗时、token、成本和质量分析有什么帮助。

**时长与时间轴（约 180 秒）**

| 时间 | 口播 | 画面 |
|---|---|---|
| 0–12s | “如果检索和模型调用都只记成‘一个步骤’，你会失去最关键的排错线索。” | 两个节点被错误合并，再拆开。|
| 12–40s | “Span 用来描述一个有开始和结束的处理步骤，例如检索、解析、工具调用或业务函数。Generation 专门表达一次模型生成。” | 左侧 Span，右侧 Generation；给出抽象例子。|
| 40–80s | “分开后，Span 帮你看流程耗时；Generation 还能关联模型名、提示词、输出以及 token 或成本字段——前提是 SDK、模型供应商和配置提供了这些数据。” | 流程计时器与 Generation 元数据卡。|
| 80–120s | “演示一条 RAG 链路：检索是 Span，回答模型是 Generation。先比较各节点时长，再看模型调用的输入输出和用量。” | Trace 树逐节点展开；显示“示意”标签。|
| 120–150s | “不要把类型名当成质量结论。记录得更细，只代表证据更完整；评分仍需要单独的评测或人工标准。” | 记录完整度 ≠ 质量分数。|
| 150–172s | “做代码审查时，检查三件事：节点边界是否稳定、模型调用是否有 Generation、失败时是否仍能结束并上报。” | 三项 checklist。|
| 172–180s | “下一步我们会用 Prompt 和数据集，把可观察变成可比较。” | 片尾卡。|

**可运行演示步骤**

1. 准备一个最小 RAG 或工具调用函数，不使用真实敏感数据。
2. 按当前 SDK 示例记录检索/工具函数为 Span。
3. 按当前 SDK 示例记录模型请求为 Generation，并保存模型名与输入输出。
4. 让模型调用失败一次，确认父 Trace 仍可结束、错误信息可定位。
5. 在 UI 对比 Span 与 Generation 的时长和元数据字段；字段不存在时说明“取决于 SDK/供应商配置”。

**官方来源**

- Observability 数据模型：<https://langfuse.com/docs/observability/data-model>
- Tracing SDK：<https://langfuse.com/docs/sdk>
- Prompt 管理入口：<https://langfuse.com/docs/prompt-management>

**事实边界**：token、成本、模型元数据是否完整取决于模型供应商返回值、SDK 版本和配置；不得把缺失字段口播成“Langfuse 没有该能力”。

## 统一拍摄与核验门

- 每集只讲一个概念和一个观众动作。
- 录屏前锁定 Langfuse 版本、SDK 版本、运行日期和官方 URL。
- 所有密钥、真实用户输入、内部 Prompt 和个人信息脱敏。
- 代码画面必须与实际运行命令一致；未运行的代码标记为“示例”。
- 任何“支持”“自动”“准确”“降低成本”等强断言，都要回到官方文档或本地运行证据。
- 每集结尾明确：本集证明了什么、没有证明什么、下一集依赖什么。
