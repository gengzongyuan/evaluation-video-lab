# 3分钟评测科普视频：可复用生产模板

## 1. 系列定位

**系列名建议：**《3分钟看懂一次评测》

**一句话承诺：**每集只解决一个评测判断问题，用一个可复核的证据把“感觉”变成“决定”。

**目标观众：**产品、研发、测试、运营，以及想判断 AI/软件宣传是否可信的普通用户。

**每集交付物：**一条 9:16、约 180 秒的视频；一张证据卡；一个可复制的检查动作；一条评论区问题。

## 2. 固定结构（180秒）

| 时间 | 内容 | 画面/声音 | 质量门 |
|---|---|---|---|
| 0–08s | 反常识钩子：一个“看起来对、其实不够”的结论 | 大字问题 + 结果局部放大；先给冲突 | 不用夸张结论，问题必须可验证 |
| 08–25s | 场景：谁遇到什么决策 | 人物/产品界面/测试记录三选一 | 说清受影响的人和决策 |
| 25–65s | 规则：本集只讲一个评测概念 | 白板式动画，最多 3 个关键词 | 术语给出普通话解释 |
| 65–120s | 证据演示：输入、方法、结果 | 屏幕录制/表格/日志；关键数字逐项标注 | 交代样本、版本、日期、条件 |
| 120–150s | 结论分层：能证明什么、不能证明什么 | 绿/黄/红三色证据卡 | 不能把局部结果扩成产品总评 |
| 150–172s | 决策动作：观众下一步怎么查 | 3步清单，动作动词开头 | 观众能在5分钟内复现 |
| 172–180s | 记忆点 + 评论问题 | 固定片尾板 | 问题必须能带来下一集素材 |

## 3. 视觉与镜头语言

- **画幅：**9:16，1080×1920；重要文字放在安全区中央，避免被平台按钮遮挡。
- **镜头节奏：**平均每 2–4 秒一次信息变化；证据画面允许停留 5–8 秒，给观众读数时间。
- **色彩：**深灰背景 + 米白正文 + 橙色“待核验” + 绿色“已证实”；红色只表示“不可据此下结论”，不表示对象一定失败。
- **字幕：**口播逐句出字，每行不超过 14 个汉字；数字、版本、日期采用等宽字体或高对比标签。
- **证据卡片：**固定五格：`问题 / 样本 / 方法 / 结果 / 边界`。每格只放一句话。
- **屏幕录制：**先展示原始输入，再展示执行过程，最后展示结果；不可只放精修截图。

## 4. 证据卡片模板

```text
【问题】这次评测想判断什么？
【样本】多少条、来自哪里、时间范围？
【方法】用什么版本、提示词、参数、评分规则？
【结果】原始数字、分组、失败例各是什么？
【边界】哪些结论仍不能推出？
【复现】观众下一步打开什么、输入什么、看哪个字段？
```

**证据等级：**

- L0：观点/体验，只能作为选题线索。
- L1：单次演示，可说明“这次发生了什么”。
- L2：固定条件下的多样本结果，可支持局部比较。
- L3：跨版本/跨模型、公开方法与原始数据齐全，可支持较稳健决策。

视频结论必须和证据等级匹配。没有 L2 以上证据时，标题使用“我怎么查/一次演示”，不要使用“谁最好/全面领先”。

## 5. 单集制作清单

1. 写一句话结果：看完后观众能做哪个判断？
2. 写证据表：样本、版本、日期、条件、原始结果和失败例。
3. 先录“原始过程”，再剪钩子和节奏；保留未剪辑文件。
4. 生成五格证据卡，逐格对照口播。
5. 做桌面与手机两种观看检查：数字是否读得出、字幕是否被遮挡。
6. 让一名不了解背景的人只看前 30 秒，复述本集问题；复述错误则重写钩子。
7. 发布前检查：没有未验证的推荐、没有隐去条件、价格/版本/日期已标注。

## 6. 发布元数据模板

```yaml
title: "3分钟看懂：<一个判断问题>"
hook: "<前8秒反常识问题>"
claim_level: L1|L2|L3
sample: "<数量/来源/日期>"
method: "<版本/条件/评分方法>"
cta: "评论区告诉我：你还想查哪个条件？"
assets:
  - raw-input
  - raw-run-log
  - evidence-card
  - subtitles
status: draft|fact_checked|ready_to_edit|published
```

## 7. 风险与禁区

- 未买样、未实测、未拿到原始数据的对象，不写成推荐、同款或平替。
- 单个截图、单条样本、一次成功演示不能代表整体能力。
- 不把“评分高”直接翻译成“更适合所有人”；必须说明任务、权重和失败例。
- 引用外部数字时保留原链接、检索日期和上下文；无法核验就降级为待查线索。
- 真实用户数据、内部提示词、密钥和个人信息进入画面前必须脱敏。

## 8. 可扩展选题池

- 为什么“平均分第一”仍可能不适合你的任务？
- 一次评测至少要公开哪五个条件？
- 失败样本为什么比冠军截图更有用？
- 同一模型换个提示词，分数变化说明了什么？
- 评测报告里的“显著提升”到底要看什么？

## 交接

**结论：**用固定时间轴、五格证据卡和 L0–L3 证据等级，可以把每集控制在同一生产标准内。

**我的理解：**首轮重点是建立可复用系统，不假装已有真实实验数据。

**隐含假设：**视频由一人或小团队制作，素材以屏幕录制、表格和旁白为主。

**能证明的范围：**模板覆盖脚本、镜头、证据、发布元数据和质量门禁。

**不能证明的范围：**尚未证明观众留存、平台分发效果或具体模型结论。

**与其他 agent 的冲突：**无；具体选题与脚本由其他任务决定。

**需要冻结的字段：**证据等级、样本/版本/日期、结论边界、片尾 CTA。

**依据：**可复核性优先；先展示条件和原始过程，再给结论。

**产物：**本文件。

**验证：**`test -s evaluation-video-lab/content/agent-v03-format.md`。

**风险/缺口：**尚无真实素材和剪辑工程模板。
